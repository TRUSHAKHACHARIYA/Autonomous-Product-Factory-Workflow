Building the Agent Pipeline
on Claude API

Yes — you can build the entire 18-agent automation using Claude's API. Here's exactly how it works.

💡 Short Answer

Yes, absolutely. Each "agent" in your pipeline is simply a Claude API call with a specific system prompt that defines its role, inputs it receives, and outputs it should produce. Your code (Python/Node.js) acts as the Orchestrator — it calls Claude for each agent in sequence, passes the output of one agent as the input to the next, and stores everything in a Shared Context Store (a database or file system). Claude does the thinking; your orchestrator does the routing.

Step-by-step: what actually happens at runtime
1
User submits project description
Your UI collects the requirement. Orchestrator starts pipeline. Creates a unique run_id and initializes the Shared Context Store.
2
Orchestrator calls Claude for Agent #2 — Requirement Analyst
Passes system prompt defining the analyst role + user input as the message. Claude responds with structured requirements.
POST /v1/messages
system: "You are a Requirement Analyst. Extract FR, NFR, personas..."
user: "Build me a SaaS CRM with payments and notifications"
→ Claude returns: requirements.md, personas.md, complexity_score.json
3
Output saved to Shared Context Store
Orchestrator parses Claude's response and saves each file to the database. All future agents will load these files as context.
4
Repeat for each sequential agent (PM → Arch → Security → Design)
Each agent gets: its unique system prompt + all relevant outputs from previous agents loaded into the context. The chain grows richer at each step.
// PM Agent gets requirements from analyst
system: "You are a Project Manager. Create epics from requirements..."
user: [requirements.md content] + "Create sprint plan"
→ returns: epics.md, tasks.json, sprint_plan.md
5
HITL Checkpoint — Pipeline pauses, human is notified
After PM Agent, orchestrator stops and sends a notification (email/Slack/webhook). Human reviews the epic/scope. On approval, orchestrator resumes from the next step.
6
Parallel execution — Frontend & Backend Junior agents
Orchestrator fires 4 Frontend Junior API calls simultaneously using Promise.all() (Node) or asyncio.gather() (Python). Each Junior gets a different module-specific system prompt.
// Fire all 4 juniors at once
await Promise.all([
  callClaude("auth_module_agent", context),
  callClaude("dashboard_agent", context),
  callClaude("admin_panel_agent", context),
  callClaude("shared_components_agent", context)
])
7
Fix Loop — Orchestrator manages retries automatically
QA Agent returns bug_report.json. Orchestrator loops: assigns bug → calls Claude to fix → calls Claude to retest. Max 3 retries. On failure, notifies human.
8
Pipeline complete — Final product delivered
All agents done. Orchestrator compiles final report, closes run, sends completion notification with live URLs, docs links, and cost report.

For a custom multi-agent pipeline, you'd build the orchestrator yourself using the Anthropic Python/Node SDK and wire the agents together as described above.
Minimal orchestrator code pattern
Core Pattern — How Every Agent Call Looks in Code
# Every agent follows this exact pattern
import anthropic

client = anthropic.Anthropic() # your API key auto-loaded from env

async def run_agent(agent_name: str, context: dict) -> dict:
    # 1. Build system prompt for this specific agent
    system_prompt = AGENT_PROMPTS[agent_name]
    
    # 2. Load relevant context files from shared store
    relevant_files = load_context(agent_name, context["run_id"])
    
    # 3. Call Claude API
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=8096,
        system=system_prompt,
        messages=[{"role": "user", "content": relevant_files}]
    )
    
    # 4. Parse output and save to shared context
    outputs = parse_agent_output(response.content[0].text)
    save_context(context["run_id"], agent_name, outputs)
    return outputs

# Run parallel junior agents
results = await asyncio.gather(
    run_agent("fe_auth", ctx),
    run_agent("fe_dashboard", ctx),
    run_agent("fe_admin", ctx),
    run_agent("fe_shared", ctx)
)
